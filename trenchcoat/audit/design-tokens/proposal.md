# Trenchcoat token standard

Companion files: [analysis.md](analysis.md) (what exists today), `tokens.css` (the dictionary), `mapping.json` (old → new, per file), `inventory.json` (every token and hard-coded value), [contrast.md](contrast.md) (generated by `scripts/contrast.mjs`: 179 pairs × 4 look/theme combinations, checked in CI; it replaces `dictionary-contrast.json`).

## 1. Naming convention

Prefix `--tc-` everywhere. It replaces `--ui-<abbr>[c]-` and the Screens' bare names (`--ink`, `--accent`, …), which collide with app tokens.

**Layer 1: primitives.** Raw values, independent of look and theme. Components don't use colour primitives directly.

| Family | Tokens |
|---|---|
| Neutrals | `--tc-gray-{0…950}` (pure greys, light themes), `--tc-zinc-{50…950}` (cool-tinted, dark themes) |
| Hues | `--tc-{blue,cobalt,green,amber,red,violet,pink}-{50,300,400,500,600,950}`: 50 light tint · 500 solid on light · 600 text on light · 300/400 text/solid on dark · 950 dark tint. `cobalt` is Clean's blue |
| Shape | `--tc-radius-{2xs 2, xs 4, sm 6, md 8, lg 10, xl 12, 2xl 16, 3xl 20, full}` |
| Space | `--tc-space-{0-5 … 16}` (n × 4px, plus the 2/6/10/14/18px half steps, up to 56/64) – exposed, not codemodded |
| Motion | `--tc-duration-{instant 90, quick 120, fast 150, base 200, moderate 260, slow 320, slower 420, slowest 560, reveal 700, reveal-slow 900}ms`, `--tc-duration-shimmer 1600ms` · `--tc-ease-{standard (= ease), out, decelerate (= the ease-out keyword), emphasized, in-out, in, spring}` |
| Type | `--tc-font-sans`, `--tc-font-mono`, `--tc-font-size-{2xs 10 … 4xl 28}` plus `-plus` half steps (`lg-plus` = 15) · `--tc-font-weight-{regular, medium, semibold}` · `--tc-line-height-{none 1, tight 16, snug 18, normal 20, relaxed 22, loose 24, display-sm 28, display 32}` · `--tc-tracking-{tight, snug, normal, caps}` |
| Layers | `--tc-z-{sticky 10, dropdown 30, drawer-scrim 40, drawer 50, modal-scrim 60, modal 70, toast 80, drag 90}` |

**Layer 2: semantic.** `--tc-<category>-<role>[-<state>]`.

| Category | Tokens |
|---|---|
| Text | `text-strong`, `text-primary`, `text-secondary`, `text-muted`, `text-placeholder` (own value, ≥ 4.5), `text-disabled` (decorative/disabled only), `text-on-accent`, `text-on-inverse` |
| Icons | `icon-muted` (≥ 3:1) |
| Surfaces | `surface-base`, `surface-raised` (card, panel), `surface-overlay` (menu, popover), `surface-sunken` (well), `surface-tray` / `surface-on-tray`, `surface-control` (inputs, secondary buttons), `surface-inverse` (ink: primary button, inverted pill, tooltip), `surface-inverse-hover`, `surface-inverse-active` |
| Fills (translucent) | `fill-subtle`, `fill-default`, `fill-strong`, `fill-hover`, `fill-selected` |
| Borders | `border-subtle`, `border-default` (decorative), `border-strong`, `border-control` (≥ 3:1 where the edge is the only cue), `border-control-hover`, `border-selected` (≥ 3:1) |
| Focus | `focus-ring`, `focus-ring-width`, `focus-ring-offset` (per look), `focus-outline` (shorthand), `focus-halo` + `focus-halo-width` (decorative field halo) |
| Accent | `accent`, `accent-hover`, `accent-text`, `accent-subtle`, `accent-highlight` |
| Status | `status-{success,warning,danger,info}-{fg,bg,border,solid}` – fg ≥ 4.5:1, solid ≥ 3:1 |
| Data vis | `chart-1…6`, `chart-neutral` |
| Tones | `tone-{violet,pink,amber,rose}-{fg,bg,border,solid}` |
| Elevation | `shadow-control`, `shadow-raised`, `shadow-raised-hover`, `shadow-overlay`, `shadow-sunken` (well edge) |
| Effects | `shimmer`, `scrim` |
| Look-level scale | `hairline` (1 / 0.5px), `font-weight-strong` (600 / 500), `ease-move` (out / emphasized), `radius-badge` (full / 5px) |

**Layer 2b: pattern tokens.** One recipe per UI pattern, valued per look, built from layer 2:
`control-{h,radius,px}-{sm,md,lg}`, `control-font-{size,weight}`, `action-{primary,secondary,ghost}-*`, `field-*`,
`menu-*`, `menu-item-*`, `pill-*`, `kbd-*`, `switch-*`, `seg-*`, `card-*`, `tray-{inset,radius}`, `avatar-*`,
`caption-*`, `eyebrow-*`, `meter-*`, `tooltip-*`, `divider`. Values and when to use each: §7 and CONTRIBUTING.md.

One word per concept: `ink`/`fg`/`body` → `text-primary`; `line`/`edge`/`grid` → `border`; `tray`/`well` → `surface-sunken`; `wash`/`fill`/`chip` → `fill`; `solid`/`primary` button → `surface-inverse`; `ok`/`done`/`good`/`up` → `status-success`. "Faint" is gone: readable text is `text-muted`, decorative or disabled text is `text-disabled`.

**Layer 3: component tokens.** `--tc-<component>-<part>-<property>[-<state>]` with the full slug, defined once from semantic tokens – no dark block, no look block:

```css
.ui-button { --tc-button-primary-bg: var(--tc-surface-inverse); }
```

Add one only for a real theming knob or a value with no semantic equivalent (geometry, entity colours, chart series, illustration art). Values that genuinely differ by look (Standard's button gradient, 1px vs 0.5px rings) go in a `:where([data-tc-look="clean"], [data-look="clean"]) .ui-…` rule, never a forked token name.

## 3. Selection mechanism

- **Look:** `[data-tc-look="standard|clean"]` on any ancestor; `[data-look]` on a component root (the `look` prop). Nearest wins; none means Standard.
- **Theme:** every colour token is `light-dark(LIGHT, DARK)`, so the theme is just `color-scheme`. One selector list,
  in `tokens.css` and inlined into every published file by `build-lib.mjs` (`THEME_RULES` in `scripts/tokens.mjs`):

  | Selector | color-scheme |
  |---|---|
  | `.dark`, `[data-theme="dark"]`, `[data-tc-theme="dark"]` | `dark` |
  | `[data-theme="light"]`, `[data-tc-theme="light"]` | `light` |
  | `[data-tc-theme="system"]` | `light dark` (follows the OS) |
  | no attribute, with `tokens.css` | `light dark` on `:root` (follows the OS) |
  | no attribute, a lone published file | the page's own `color-scheme` (opt in with `:root { color-scheme: light dark }`) |

  The `.dark` class and the `color-scheme` paths give identical token colours (checked in a browser for both looks,
  including OS dark via `prefers-color-scheme`). Component rules scoped to `.dark` don't follow the attribute or the
  OS – that is why they're banned for new code (CONTRIBUTING.md, guard rails). Because unregistered custom properties keep `light-dark()` unresolved until use, look and theme nest independently in any order (verified in a browser for all 7 nesting cases).
- **Overrides:** all selectors are in `:where()`, so `:root { --tc-accent: … }` wins regardless of load order.
- **Support:** `light-dark()` needs Chrome/Edge 123, Firefox 120, Safari 17.5; an `@supports not` fallback (section 4 of `tokens.css`, generated by `node scripts/tokens.mjs` from the look blocks, so it always covers every colour token) handles the common nestings, the attribute, the classes and OS dark.

## 4. Shipping: optional `tokens.css` + build-inlined fallbacks

The build rewrites each `var(--tc-x)` to `var(--tc-x, light-dark(L, D))` using the file's own look: `<slug>.tsx` gets Standard values, `<slug>-clean.tsx` Clean values (and defaults its `look` prop to `"clean"`). A copied file therefore renders correctly in light and dark with no setup; adding `tokens.css` brings runtime look switching, theming and consistency. Fallbacks come from the same dictionary, so they can't drift. The dictionary lives as data (`tokens.json`) and generates `tokens.css`, the fallback map and the docs.

Rejected: a *required* `tokens.css` (breaks copy-one-file) and embedding the whole dictionary in every file (≈ 8–10 KB each, version races between copies).

## 5. Migration

Token rename **before** the Standard/Clean merge: the codemod treats both forks identically, after which their CSS differs only by look geometry, making the merge mostly mechanical.

1. Dictionary as `tokens.json` → `tokens.css` + fallback map.
2. Tooling: fallback-inlining pass per look; lint rule banning literal colours/fonts/durations and colour primitives in component CSS; `apply-mapping` codemod over `mapping.json`.
3. Codemod high/medium-confidence tokens (2,872 of 3,546); delete the 114 dead tokens and the dark blocks they made redundant.
4. Hard-coded values: durations, fonts, radii, font sizes, easings mechanically; dark-theme literal rules deleted once their light rule uses a token.
5. Manual review of the low-confidence items (674 tokens, ~1,250 literal colours, off-scale radii, shadows).
6. JS colours: chart palettes → `var(--tc-chart-n)`, dropzone file types → tone tokens, `stroke="#fff"` → `currentColor`; logos and illustration art stay literal.
7. Screens: rename App Shell's bare vocabulary to `--tc-*`.
8. Verify: visual regression across looks × themes, axe re-run, Safari 17.5 spot check.

### Added after the migration review (2026-10-24)

Four of the seven review groups independently needed a visible tray in dark mode; one needed a placeholder role:

- `--tc-surface-tray` / `--tc-surface-on-tray` – a tray that cards sit on, lighter than the page in dark (Standard `#f0f0f0 / #19191b`, card `#fff / #232326`; Clean `#f7f7f7 / #161618`, card `#fff / #1c1c1e`). Components currently express this with component tokens; the single-source merge adopts the semantic pair.
- `--tc-text-placeholder` – an alias of `text-disabled` so placeholders don't read as values (contrast for placeholders is revisited in the WCAG fixes).

Raised but not adopted (kept as component tokens): a text-shimmer token, a "well" fill, a soft non-focus halo, a translucent control border, diff-line tints. Open for the WCAG phase: Clean `--tc-accent` stays `#0060e2` in dark – graphics that need more contrast there use `accent-text` or component tokens.
